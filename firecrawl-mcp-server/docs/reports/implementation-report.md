## Deviations from the spec

1. `setup.sh` is non-interactive (sports' is interactive): it generates `.env` (token via `openssl rand -hex 32`, `HOST_PORT=8768`,
   `FIRECRAWL_API_URL`) if absent, leaves a valid existing one alone, and `--force` regenerates with a timestamped backup. This lets the
   scripted flow run without a TTY.
2. `PORT` accepts `0` (ephemeral) so tests can bind random ports; all other ports require 1-65535.
3. `smoke.sh` uses `python3` (as sports does) rather than Node, and its step 6 aborts a half-sent POST on a raw socket then re-checks `/healthz`.
   It also checks that a wrong token gives 401.
4. 413 for streamed bodies unpipes and drains instead of destroying the socket (destroying raced with sending the response).
5. The supervisor starts the gateway before the child is ready; `/healthz` returns 503 until the child answers, which satisfies "reports healthy only when ready".
6. The token is intentionally not passed to the child's environment (only HTTP-mode vars plus `PATH`, and `FIRECRAWL_API_KEY` if set).
