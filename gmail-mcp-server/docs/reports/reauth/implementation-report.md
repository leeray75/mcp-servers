# Re-authentication: implementation report

## Changes by file
- `src/gmail_mcp/signin.py` (new): `PendingStore` (OrderedDict, TTL 600 s, cap 8, oldest evicted, injectable clock, per-app instance) and `SignInService` with `GET /auth` and `GET /oauth2callback`; static HTML pages, security headers, 405 page for other methods, off-loop exchange via `anyio.to_thread`, scope/refresh-token checks, locked atomic write, then `on_signed_in` (= `GmailClient.reset`). One INFO log per outcome.
- `src/gmail_mcp/server.py`: `create_app` builds one `GmailClient`, shares it with `create_server`, mounts the sign-in routes; `_instrumented` now takes `host_port` and uses `GmailMcpError.user_message(host_port)`. Still no `from __future__`; still six tools.
- `src/gmail_mcp/errors.py`: `auth_url()`, `auth_hint()`, `AUTH_HINT` (default port), `GmailMcpError.user_message()`; `AuthRequiredError` overrides it so the link reflects `HOST_PORT`.
- `src/gmail_mcp/config.py`: `host_port` (1-65535, default 8765).
- `src/gmail_mcp/security.py`: `AUTH_PATH`, `CALLBACK_PATH`; bearer exemption is exact-match GET/HEAD on `/healthz`, `/auth`, `/oauth2callback`.
- `src/gmail_mcp/gmail_client.py`: public `reset()` (under the lock).
- `src/gmail_mcp/logging_setup.py`: redacts `4/0...` authorization codes.
- `src/gmail_mcp/auth_cli.py`: prompt mentions the script opens the browser (no browser logic in the CLI).
- `docker-compose.yml`, `.env.example`: `HOST_PORT` passed into containers (via the shared `x-app-env`, so the auth service gets it too); mapping still `127.0.0.1`.
- `scripts/lib/common.sh`: `open_url` (wslview, explorer.exe with status ignored, xdg-open, print; single argument, no eval/cmd) and `server_running`.
- `scripts/auth.sh`: `--no-browser`; server path (open `/auth`, poll `stat` mtime every 2 s up to 300 s, never reads contents); fallback container path streaming output line by line, opening the first `https://accounts.google.com/` URL, propagating the container exit code (`PIPESTATUS`), `PYTHONUNBUFFERED=1`. `auth.ps1` unchanged (already forwards args).
- Tests: new `tests/test_signin.py`; additions in `test_gmail_client.py` (reset), `test_config.py` (HOST_PORT), `test_logging.py` (code scrubbing); `conftest.py` (HOST_PORT cleared, `FakeGmail.reset`); `test_server.py` public-method set of `GmailClient` now includes `reset` (a necessary, non-weakening update).
- Docs: README (security model, sign-in step, scripts table, Re-authenticating, config, troubleshooting, layout), `docs/SPEC.md` (§3, §4.1, §4.2, §4.3, new §4.4, §8), CHANGELOG, CLAUDE.md.

## Notes, gaps, deviations
- Not exercised against real Google or a real browser/WSL opener (forbidden by constraints): the Flow `authorization_url` is real and tested offline; the callback exchange uses a fake Flow. `auth.sh` itself was only syntax/shellcheck checked.
- oauthlib raises `Warning` when Google narrows scopes; handled as `scope_missing`. Asserted via a fake only.
- A bug found while testing: an empty `PendingStore` is falsy (`__len__`), so `store or PendingStore()` discarded an injected store; fixed with `is None`.
- The 405 page is produced by the handler (all methods routed), so it carries the security headers; unauthenticated non-GET gets 401 first from the bearer middleware, as specified.
- `docker compose config` was not run because it would print `.env` values.
