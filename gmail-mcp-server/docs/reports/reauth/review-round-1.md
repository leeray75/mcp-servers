## Findings

1. MINOR - src/gmail_mcp/signin.py:182-191,197 (and README/SPEC residual-risk text). Eviction DoS: a web page the user visits can fire 9+ cross-site GETs at `http://127.0.0.1:<port>/auth` (e.g. image/iframe loads; Host/Origin guard passes because no Origin is sent on such loads and Host is loopback), evicting the user's legitimate pending attempt, which then shows "unknown, expired or already used". It cannot hijack or read anything (state is only in the opaque redirect). Fix: acceptable as is; optionally mention in the residual-risk paragraph that a hostile page can cause a failed sign-in (retry works), or require `Sec-Fetch-Site` in `{none, same-origin}` / absent to start an attempt.

2. MINOR - src/gmail_mcp/signin.py:184,195. `HEAD /auth` creates a pending entry (and counts against the cap of 8) although the redirect body is discarded; link-prefetchers or `curl -I` could burn slots. Fix: for HEAD on `/auth` return the redirect without calling `store.add`, or answer HEAD without side effects.

3. MINOR - scripts/auth.sh:57-71 / lib/common.sh `server_running`. If the container is running an image built before this change, `/healthz` is 200 but `/auth` is 404, so the script opens a 404 page and waits the full 5 minutes. Fix: print a one-line hint in the timeout message ("if the page showed 404, rebuild: scripts/rebuild.sh") or probe `/auth` with `curl -s -o /dev/null -w %{http_code} -X HEAD`-style check before choosing the server path (note finding 2).

4. MINOR - scripts/auth.sh:70. `compose run` without `-T` allocates a TTY when stdin is a terminal even though stdout is piped; the code already strips CR so it works, but `-T` would be cleaner and avoids terminal-control noise in the mirrored lines. Optional.

5. MINOR - docs formatting. README.md (Testing-mode note, line starting "> link (see ...") and docs/SPEC.md §4.2 ("a clear, actionable MCP tool error containing the link ... and the script fallback -") exceed the surrounding ~100-column wrap. Cosmetic: re-wrap.

No regressions found in existing behaviour; `/healthz` semantics unchanged; logs remain content-free; port still published on 127.0.0.1 only.
