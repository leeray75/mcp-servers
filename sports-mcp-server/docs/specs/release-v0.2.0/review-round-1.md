## Findings

**Blockers: none. Majors: none.**

### Minor

- **m-1 (pre-existing; flag for the human, not a spec miss) — `README.md:12` claims "three" resources; there are four.**
  `src/sports_mcp/resources.py` registers `leagues-schema`, `tools-schema`, `leagues` and `teams-guide`, and
  `server.py:272`'s own docstring says "three resources". The README Resources section itself lists all four. Why it
  matters: a release doc should be accurate on a top-level claim, and this is exactly the class of drift R3 fixed for
  settings. It predates this release and is outside the spec's listed scope, so — as a reviewer — I record it as a
  finding with a suggested fix (change "three" → "four" in `README.md:12`; fix the same word in the `create_server`
  docstring) rather than a blocker on this change.
- **m-2 (pre-existing; low impact) — README "captured in two campaigns: the league set on 2026-10-04" is slightly
  imprecise for `nba_scoreboard_final`/`nba_summary_final`.** Their dominant game dates are 2026-06-06 / 2026-07-19
  (NBA Finals, fetched via explicit `?dates=` / past-event IDs in `tools/capture_fixtures.py`). The sentence says when
  the capture ran, not when the games were played, so this is defensible house phrasing; no action required.
- **m-3 (nit, pre-existing) — `.env.example:19` `# ESPN_TIMEOUT_SECONDS=10` renders the float default `10.0` as `10`.**
  Harmless (pydantic parses both); the README already shows `10`. No action required.
- **m-4 (nit, R7) — the release commit must include the currently-untracked `docs/specs/release-v0.2.0/` directory**
  (spec §5 assigns it to this change; the report's "six files" wording plus "plus this report" makes the full set
  seven paths). Ensure the single commit's file list matches §5 exactly.
- **m-5 (judgement call — my own opinion, as requested) — "the player endpoints … for NFL, NBA and MLB" is the union
  across fixture kinds; the profile kind is NFL + NBA only (MLB profile is not exercised).** The sentence structure
  ("the player endpoints (…) for NFL, NBA and MLB") reads as a union and every named kind/sport pairing is backed by a
  file, so it is not an overclaim and **I accept it as written**. Optional precision if the human wants belt-and-braces:
  "(athlete profile for NFL and NBA)". I do not require it.
